## 2. Project Overview

The **Hospital Management System** is an enterprise-grade desktop application engineered in Java Swing that enables hospital front-desk personnel and healthcare administrators to digitally manage patient records. 

Originally built as a single-file prototype utilizing Java Object Serialization (`patients.dat`), this project has been fully upgraded into an architecturally robust, multi-tier Object-Oriented software system integrated with a persistent **MySQL 8+** relational database via **JDBC**.

---

## 3. Objectives

1. **Digitize Patient Records:** Transition hospital administrative intake from manual paperwork and flat serialized files to an ACID-compliant relational database.
2. **Demonstrate Practical OOP Principles:** Implement industry-standard object-oriented design patterns including Abstraction, Inheritance, Encapsulation, and Polymorphism.
3. **Multi-Tier Separation of Concerns:** Decouple Presentation (GUI), Business Logic (Service Layer), Data Access (DAO Layer), and Relational Persistence (Database Layer).
4. **Resilient Data Management:** Provide complete Create, Read, Update, Delete (CRUD) operations with comprehensive input validation and safe legacy data migration.

---

## 4. Implemented Features

1. **Register Patient:** Captures patient full name, age, and diagnosed medical illness/condition.
2. **Auto-Generated Patient ID:** Seamlessly retrieves and displays auto-incremented primary keys generated by MySQL.
3. **Display All Records:** Displays all registered patients in a clean, non-editable, structured `JTable`.
4. **Search Patient by ID:** Direct lookup by numeric ID with automatic form pre-population and table highlighting.
5. **Update Patient Records:** Click any patient row in the table to populate the form fields and modify details in real time.
6. **Delete Patient Records:** Safely removes patient records from the database following confirmation dialogs.
7. **Refresh Records:** Re-queries the live database to sync records immediately.
8. **Clear Form / Reset:** Resets input fields, clears table selections, and returns to registration mode.
9. **Strict Input Validation:**
   - **Name:** Non-empty, minimum 2 characters, maximum 100 characters, alphabet/hyphen/period characters only.
   - **Age:** Positive whole integer between 1 and 125 years.
   - **Condition:** Non-empty, minimum 2 characters, maximum 255 characters.
10. **Meaningful Feedback & Error Handling:** Context-aware `JOptionPane` alerts for Information, Warning, and Error conditions, plus a real-time status bar.
11. **Safe Legacy Migration:** One-click utility that imports existing records from `patients.dat` into MySQL while automatically skipping duplicates.
12. **Live Database Status Indicator:** Continuous connection health monitoring with a dedicated "Test DB Connection" tool.

## 6. OOP Concepts Implemented

| OOP Principle | Implementation in Codebase |
| :--- | :--- |
| **Classes & Objects** | System logic is organized into distinct classes (`Patient`, `Person`, `PatientDAOImpl`, `PatientService`, `DatabaseConnection`, `HospitalManagementSystem`). |
| **Encapsulation** | All entity fields in `Person` and `Patient` are declared `private`. Read and write access is strictly mediated through public getters, setters, and validation methods. |
| **Constructors** | Parameterized and overloaded constructors support different entity states (e.g., creation before ID assignment vs. retrieval with database timestamps). |
| **Inheritance** | `Patient extends Person` reuses common demographic fields (`name`, `age`) via `super(name, age)`. In the UI layer, `HospitalManagementSystem extends JFrame`. |
| **Abstraction** | - `abstract class Person` defines the template method `public abstract String getRole()`.<br>- `interface PatientDAO` specifies the persistence contract without binding consumers to SQL implementations. |
| **Polymorphism** | `Patient` overrides `getRole()` and `toString()`. The UI interacts with `PatientDAO` polymorphically. |
| **Separation of Concerns** | Distinct layer boundaries: UI (`ui`), Business Logic & Validation (`service`), Data Access (`dao`), Database Utilities (`database`), Entities (`model`), and File I/O (`util`). |

## 7. Database Design

### Database Name
`hospital_management`

### Table: `patients`

```sql
CREATE TABLE IF NOT EXISTS patients (
    patient_id INT AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    age INT NOT NULL CHECK (age > 0 AND age <= 125),
    `condition` VARCHAR(255) NOT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

> **Note on MySQL 8+ Reserved Keywords:**  
> In MySQL 8.0+, `CONDITION` is a reserved SQL keyword. All SQL statements enclose `` `condition` `` in backticks to guarantee strict syntax compliance and prevent execution errors.

## 10. How to Install and Configure MySQL

1. **Download MySQL Server:**  
   Download the MySQL Community Server or Enterprise Server installer from [dev.mysql.com/downloads/](https://dev.mysql.com/downloads/).
2. **Install & Initialize:**  
   Run the installer and complete the setup wizard. Set a secure password for the `root` administrative user (e.g., `root123`).
3. **Start the MySQL Service:**  
   Ensure the MySQL service is running via Windows Services (`services.msc`) or via the command line:
   ```powershell
   mysqld --console
   ```

## 11. How to Execute `schema.sql`

Open PowerShell or Command Prompt, navigate to the project directory, and run:

```powershell
# Using the mysql CLI client (adjust path if needed):
mysql -u root -p < schema.sql
```

Alternatively, open **MySQL Workbench**, **DBeaver**, or the MySQL CLI, open `schema.sql`, and execute the statements. This creates the `hospital_management` database and the `patients` table.

## 12. How to Configure Database Credentials

1. Locate `db.properties.example` in the project root.
2. Copy it to a new file named `db.properties`:
   ```powershell
   copy db.properties.example db.properties
   ```
3. Open `db.properties` in any text editor and supply your MySQL username and password:
   ```properties
   db.url=jdbc:mysql://localhost:3306/hospital_management?useSSL=false&allowPublicKeyRetrieval=true&serverTimezone=UTC
   db.user=root
   db.password=YOUR_LOCAL_MYSQL_PASSWORD
   db.driver=com.mysql.cj.jdbc.Driver
   ```
4. `db.properties` is protected by `.gitignore` so your local credentials will never be exposed on GitHub.

## 13. How to Compile and Run the Application

### Option A: Using Windows 1-Click Scripts (Recommended)

1. **Compile the Project:**
   ```powershell
   .\build.bat
   ```
   This compiles all packages into `bin/` and packages `HospitalManagementSystem.jar`.

2. **Launch the Application:**
   ```powershell
   .\run.bat
   ```

### Option B: Manual Command-Line Execution

```powershell
# 1. Compile
javac -encoding UTF-8 -cp ".;lib\mysql-connector-j-26.7.0.jar" -d bin src\main\java\model\*.java src\main\java\database\*.java src\main\java\dao\*.java src\main\java\service\*.java src\main\java\util\*.java src\main\java\ui\*.java

# 2. Run
java -cp "bin;lib\mysql-connector-j-26.7.0.jar;." ui.HospitalManagementSystem
```

### Option C: Using Maven (If Maven is installed)

```powershell
# Compile and test
mvn clean compile

# Run via Maven
mvn exec:java -Dexec.mainClass="ui.HospitalManagementSystem"
```
